# AssumeコマンドのAWS認証チェーン改善について

## 目的

## プラン

`src/cmd/assume.rs` の `generate_sdk_config()` 関数（L63-84）に2点の問題がある：

1. **`ProfileFileCredentialsProvider` → `profile_name()`**: プロファイルを `credentials_provider()` として注入していると、認証情報のみが解決され、プロファイルの region 設定が引き継がれない。`config_loader.profile_name(profile)` に変更することで SDK がプロバイダーチェーン全体でプロファイルを適用する。

2. **`region` の無条件設定**: `source.region` が未指定でも `us-east-1` を無条件に設定し、プロファイルや環境変数の region 設定を上書きしてしまっている。`source.region` が `Some` の場合のみ設定し、`None` の場合は SDK プロバイダーチェーンに委ねるべき（ただし、region が解決できない場合のフォールバック設計も検討が必要）。

実装は別タスク（0009以降）で行う。

**主な知見**：
- `ProfileFileCredentialsProvider` の問題: 認証情報のみを注入するため、プロファイルの region 設定が引き継がれない
- `region` の無条件設定問題: us-east-1 がデフォルトで上書きされ、プロファイルや環境変数の region 設定が無視される
- フォールバックとして us-east-1 を残すこと自体は問題ない（エラーより動く方が良い）。問題は「無条件上書き」であること
- 実際の修正は検証を伴う別タスクで行うことを推奨
